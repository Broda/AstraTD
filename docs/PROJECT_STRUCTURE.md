# Project structure

The project root contains Godot configuration, the launcher, and repository overview/task documents. Runtime content uses lowercase snake_case paths. Scene-specific scripts live beside their scenes; shared data, services, and effects have separate homes. The UI is currently constructed in code, so its node scripts live in `scenes/ui/` ready for related UI scenes.

```text
project.godot
Launch.cmd
scenes/
  gameplay/             Main scene and its session/simulation script
  ui/                   Menu, map-preview, and fleet-inspector node scripts
scripts/
  data/                 Shared map, wave, enemy, fleet, and upgrade definitions
  services/             Save storage, settings, and audio management
  effects/              Shared procedural effects
  fleet/                Shared target selection and Nova drone controllers
assets/
  models/<model_id>/     GLB plus that model's imported texture images
  textures/             Shared editable PBR texture maps
  icons/                Fleet portraits and shared interface symbols
  audio/                Generated music and sound effects
  shaders/              Background and wormhole shaders
art/
  models/               Editable Blender sources with packed textures
  .gdignore
tools/
  asset_pipeline/       Blender generation/rendering and Python audio tools
  .gdignore
tests/                  Automated scripts and run_checks.ps1
docs/
  screenshots/          Published gameplay and interface screenshots
  model_previews/       Model galleries and detail renders
  .gdignore
work/                   Ignored local logs, captures, and temporary checks
.godot/                 Ignored Godot-generated cache; never source content
```

## Where new files belong

- Put a scene and the script specific to it together under an appropriate `scenes/` feature folder. A future fleet or enemy scene can have its own feature folder when that scene exists; do not create placeholder folders for speculative content.
- Put reusable non-scene logic under `scripts/` by responsibility. Keep content definitions under `scripts/data/`; add authored Godot resources beside the feature that owns them when needed.
- Keep exported models and their extracted textures together under `assets/models/<model_id>/`. Runtime lookup uses `res://assets/models/<model_id>/<model_id>.glb`. Put shared original texture maps under `assets/textures/`.
- Keep `.blend` authoring sources in `art/models/`. They pack their images; Godot consumes exported GLBs and does not require Blender to launch.
- Keep generation tools in `tools/asset_pipeline/`. Both model generators write `<asset_root>/models/<model_id>/<model_id>.glb`; `WARDENS_ASSETS` overrides the asset root, not an individual model directory. Shared texture generation writes `<asset_root>/textures/`. The expansion generator consumes the project's shared maps.
- The icon tools read `art/models/`, write runtime icons to `assets/icons/`, and write review renders to `docs/model_previews/`. The audio generator writes `assets/audio/`. Commands remain runnable from any current directory when given the script's path.
- Put documentation pictures under `docs/`. The gameplay capture command writes `docs/screenshots/gameplay.png`. Temporary UI/performance outputs stay under `work/`.

## Resource moves and import boundaries

Prefer the Godot FileSystem dock for future interactive moves. When performing an external move, preserve the matching `.uid` and `.import` files and update all literal and dynamically assembled paths, project settings, scenes, tests, and asset generators. UID sidecars stay versioned. Import caches under `.godot/` are regenerated by Godot and must not be committed.

`art/`, `tools/`, and `docs/` have `.gdignore` files because the game never loads their contents. The launcher and check runner create `work/.gdignore` before importing. `.gitignore` alone does not prevent Godot from scanning a folder. Keep `tests/` importable: the development runtime loads its check scripts through `res://tests/`.

The project name, `user://wardens/` storage location, stable content IDs, and serialized save format are unchanged by this layout. Reorganization does not require a save migration.

## Validation

Run `tests/run_checks.ps1 -CaptureUI` from the repository root for import, content, storage/settings/audio, combat, integration, menus, balance, performance, rendered UI, and fresh-process display checks. Use the root `Launch.cmd` or import the root `project.godot` to play. The startup scene is `res://scenes/gameplay/main.tscn`.

After a resource move, validate a clean project copy without `.godot/` as well as the working checkout: cached import paths must not hide a missing dependency. Check that model/source bytes and script/shader UIDs survive the move; let Godot refresh the moved assets' import-cache destinations.

References: [Godot project organization](https://docs.godotengine.org/en/4.7/tutorials/best_practices/project_organization.html), [Godot resource UIDs and external moves](https://godotengine.org/article/uid-changes-coming-to-godot-4-4/).
